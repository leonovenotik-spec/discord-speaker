# Discord Speaker

[![CI](https://github.com/leonovenotik-spec/discord-speaker/actions/workflows/ci.yml/badge.svg)](https://github.com/leonovenotik-spec/discord-speaker/actions/workflows/ci.yml)
[![Python](https://img.shields.io/badge/Python-3.12%2B-3776AB?logo=python&logoColor=white)](https://www.python.org/)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

Бот, который озвучивает написанный текст в голосовом канале Discord.
Управление работает прямо с телефона: открой панель, выбери голос и введи фразу.
На время речи бот отключает твой микрофон на сервере, а затем снимает поставленный им мут.

Бот работает на хостинге или постоянно включённом компьютере. Установка на сервер сама
по себе его не запускает. Звук воспроизводится от имени бота.

## Возможности

- Личная панель `/panel` с кнопками «Озвучить» и «Стоп».
- Шесть голосов и пять скоростей речи с сохранением настроек.
- Озвучка фраз длиной до 500 символов через форму или команду `/say`.
- Восстановление серверного микрофона после завершения, ошибки или перезапуска.
- Работа на любом сервере, куда добавлен бот: по умолчанию для всех участников.
- Необязательный доступ по роли, настраиваемый отдельно на каждом сервере.
- Русские названия голосов, кнопки и сообщения.
- Постоянное подключение к голосовому каналу до выхода вызвавшего участника.
- Очередь автоозвучки сообщений из выбранного текстового канала.

| Команда | Действие |
| --- | --- |
| `/panel` | Открыть личную панель: голос, скорость и ввод текста |
| `/say text:…` | Озвучить фразу; необязательные поля `voice` и `speed` меняют сохранённые настройки |
| `/stop` | Остановить свою речь; управляющий сервером может остановить любую |
| `/restore` | Восстановить только свой микрофон после незавершённого действия бота |
| `/access` | Посмотреть настройки доступа на этом сервере |
| `/access role:…` | Разрешить озвучку выбранной роли |
| `/access everyone:True` | Снова разрешить озвучку всем участникам |
| `/textchannel channel:…` | Назначить канал автоозвучки новых сообщений |
| `/textchannel disable:True` | Выключить автоозвучку сообщений |
| `/leave` | Выйти из голосового канала и очистить очередь; доступно вызвавшему участнику и управляющим |

Панель действует 15 минут. После истечения срока или перезапуска снова введи `/panel`.
Команды обновляются при запуске и при добавлении бота на сервер. Если меню Discord
показывает старый список, перезапусти клиент и попробуй команду в текстовом канале сервера.

## Доступ на серверах

По умолчанию озвучкой может пользоваться любой участник. Настройки `/access` меняют
владелец сервера и участники с правом **«Управлять сервером»**. Они также могут
пользоваться озвучкой независимо от выбранной роли. Удаление выбранной роли не открывает
доступ всем: управляющий должен выбрать другую роль или явно включить `everyone`.

Голос и скорость хранятся отдельно для каждого участника на каждом сервере.
В разных серверах речь может звучать одновременно; внутри одного сервера — одна фраза
за раз. Для сообщений текстового канала есть очередь до 20 ожидающих фраз;
при занятом боте `/say` предложит дождаться окончания. Каждый может остановить
свою фразу и восстановить только свой микрофон; `/restore` доступна даже после потери роли.

## Голосовой сеанс и текстовый канал

Первая фраза подключает бота к голосовому каналу автора. Бот остаётся там между
фразами и выходит, когда первый вызвавший участник покидает или меняет канал,
когда в канале не остаётся людей, либо по `/leave`. Речь других участников
того же канала не меняет владельца сеанса. Перетягивать активного бота в другой канал
командой озвучки нельзя. Выход завершает сеанс и очищает очередь.

Первое подключение и синтез выполняются параллельно; следующие фразы используют уже
открытое соединение. Подготовка речи всё ещё зависит от онлайн-сервиса TTS.
Во время воспроизведения ответ на `/say` показывает «Озвучиваю…».

Для озвучки обычных сообщений:

1. Владелец приложения включает **Message Content Intent** в Discord Developer Portal →
   Bot → Privileged Gateway Intents и перезапускает бота. При запуске бот сам проверяет
   разрешённый флаг; без него `/panel` и `/say` продолжают работать.
2. Управляющий сервером выбирает канал через `/textchannel channel:#озвучка`.
   Боту нужно право просматривать этот канал; право отправлять сообщения позволит
   сообщать об ошибках и заполненной очереди.
3. Участники заходят в один голосовой канал и пишут обычные сообщения в выбранный
   текстовый канал. Используются их личные голоса, скорости и ограничения по роли.

Автоозвучка по умолчанию выключена. Обрабатываются только новые текстовые сообщения
в выбранном канале: без истории, ботов, вебхуков и вложений. Автор должен находиться
в голосовом канале бота или вызвать новый сеанс своим первым сообщением.
При смене голосового канала ожидавшая фраза пропускается. Отключение текстового канала
или смена настройки очищает ожидающие сообщения; текущая фраза может завершиться.

## Голоса

| Голос | Тип |
| --- | --- |
| Дмитрий | Мужской, русский |
| Светлана | Женский, русский |
| Эндрю | Мужской, многоязычный |
| Брайан | Мужской, многоязычный |
| Ава | Женский, многоязычный |
| Эмма | Женский, многоязычный |

Многоязычные голоса поддерживают русский; акцент может отличаться.
Скорость: медленно, чуть медленнее, обычно, чуть быстрее или быстро.
При первом запуске выбраны Дмитрий и обычная скорость.

## Запуск

Если у тебя уже есть круглосуточно работающий Linux-компьютер, используй
[инструкцию для своего сервера](docs/linux-server.md): без отдельной платы за хостинг,
с сервисом и автозапуском. Белый IP и открытие входящих портов не нужны.

Подробная [инструкция на русском](docs/setup.md) описывает создание бота,
права Discord и запуск Railway с телефона. ID сервера для работы не нужен.

Минимальные настройки среды:

| Переменная | Назначение |
| --- | --- |
| `DISCORD_TOKEN` | Секретный токен бота из Discord Developer Portal |
| `DATA_DIR` | Каталог состояния; по умолчанию `data`, в Docker — `/app/data` |

Для Docker скопируй `.env.example` в `.env`, заполни токен и ID, затем выполни:

```sh
docker build -t discord-speaker .
docker run --rm --env-file .env -v speaker-data:/app/data discord-speaker
```

Для Railway подключи этот репозиторий, укажи переменные в настройках сервиса и
добавь постоянный диск по пути `/app/data`. Запускай одну реплику сервиса.
Хостинг может быть платным. Публичный домен и HTTP-порт боту не нужны.

## Как работает микрофон

Бот использует серверный мут. Во время подготовки речи твой микрофон ещё включён.
Если ты выключил его своей кнопкой Discord, бот эту кнопку не включает.
Уже установленный серверный мут бот не снимает и при нём отказывается озвучивать текст.
Поддерживаются обычные голосовые каналы; трибуны не поддерживаются.

Для восстановления после аварийного завершения нужен постоянный диск. При следующем
запуске бот пробует снять поставленный им мут; если ты вышел из канала, восстановление
повторяется при возвращении. Также доступна `/restore`.
Если хостинг недоступен, серверный мут можно снять вручную в Discord.
Во время озвучки не переключай серверный мут вручную: Discord хранит одно состояние
и не позволяет отличить повторный мут модератора от мута бота.

## Данные и доступ

Текст отправляется онлайн-сервису Microsoft Edge TTS для синтеза речи.
Бот не записывает разговор и подключается с отключённым входящим звуком.
Временный аудиофайл удаляется после обработки; текст и токен не записываются в журнал.
На диске хранятся только голос, скорость и ID для восстановления микрофона.
Также сохраняется ID роли, если на сервере включено ограничение доступа.
Если настроена автоозвучка, сохраняется и ID выбранного текстового канала.

Токен хранится в переменных среды хостинга или локальном `.env` и не должен попадать в Git.
Права бота: **View Channels**, **Connect**, **Speak**, **Mute Members**.
Для `/say` и `/panel` привилегированные intents не нужны. Для чтения обычных сообщений
в назначенном канале нужен **Message Content Intent**. Другие привилегированные intents не запрашиваются.
Сообщения других каналов не обрабатываются и общий кэш сообщений Discord отключён.

## Разработка и проверки

Требуются Python 3.12+ и зависимости из `requirements.txt`.
FFmpeg поставляется через пакет `imageio-ffmpeg`, отдельно устанавливать его не требуется.

```sh
python -m venv .venv
# Активируй виртуальное окружение для своей ОС.
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Для локального запуска задай переменные среды и выполни `python bot.py`.
Файл `.env` сам по себе при таком запуске не загружается.

Тесты проверяют восстановление микрофона, права доступа, сохранение настроек,
регистрацию команд, работу формы, независимость серверов и ролевые ограничения.
Они не требуют токена и не подключаются к Discord.
CI запускает их на Python 3.12 и 3.14. Реальное подключение, права и слышимость речи
нужно отдельно проверить на своём сервере после развёртывания.

```text
bot.py                 команды, панель, озвучка и восстановление микрофона
storage.py             настройки серверов, участников и журнал восстановления
tests/test_bot.py      проверки без внешних сервисов
tests/test_access.py   роли, изоляция серверов и управление своей речью
tests/test_sessions.py подключение, выход, очередь и автоозвучка сообщений
docs/setup.md          инструкция по установке и хостингу
docs/assets/avatar.png аватарка бота
Dockerfile             контейнер для запуска
railway.toml           настройки сборки и перезапуска Railway
```

При обновлении старой версии оставшийся `GUILD_ID` не ограничивает работу бота:
он используется только для удаления старых серверных команд перед их обновлением.
Команды публикуются отдельно на каждом сервере; устаревший общий список удаляется,
чтобы Discord не показывал дубликаты. Старая запись мута переносится в каталог участника.
Старые общие настройки голоса не смешиваются с новыми личными настройками.

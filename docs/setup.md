# Самостоятельный запуск

Эта инструкция предназначена для владельцев собственного экземпляра бота.
Чтобы пользоваться уже работающим ботом, достаточно
[добавить его на сервер](https://discord.com/oauth2/authorize?client_id=1561162956358549504&scope=bot%20applications.commands&permissions=7408640&integration_type=0)
и открыть `/panel`. Токен и хостинг при этом не нужны.

## Приложение Discord

1. Создайте приложение в [Discord Developer Portal](https://discord.com/developers/applications).
2. В разделе **Bot** получите токен через **Reset Token**.
   Храните его в настройках окружения, не публикуйте в GitHub и отчётах об ошибках.
3. В **Installation** включите **Guild Install**, выберите scopes `bot`
   и `applications.commands`.
4. В правах выберите **View Channels**, **Send Messages**, **Read Message History**,
   **Connect**, **Speak**, **Mute Members**.
5. В **Bot → Privileged Gateway Intents** включите **Message Content Intent**,
   если нужна озвучка обычных сообщений. Для `/say` и `/panel` этот intent не требуется.
6. Добавьте приложение на сервер по его **Install Link**.
   Для установки другими пользователями должен быть включён **Public Bot**.

Используйте ссылку именно своего приложения: приглашение из README относится к
публичному экземпляру Discord Speaker. ID сервера для запуска не нужен;
команды регистрируются на каждом сервере при подключении бота.

[Документация Discord по установке приложений](https://docs.discord.com/developers/quick-start/getting-started).

## Настройки окружения

| Переменная | Назначение |
| --- | --- |
| `DISCORD_TOKEN` | Секретный токен созданного приложения |
| `DATA_DIR` | Каталог состояния; по умолчанию `data`, в Docker — `/app/data` |

Каталог состояния должен сохраняться между перезапусками. В нём находятся настройки
серверов и участников, а также записи для восстановления микрофонов после сбоя.
Для одного токена запускайте один экземпляр процесса.

## Docker

Скопируйте `.env.example` в `.env` и укажите токен:

```sh
cp .env.example .env
```

Соберите и запустите контейнер:

```sh
docker build -t discord-speaker .
docker run -d --name discord-speaker --restart unless-stopped \
  --env-file .env -v speaker-data:/app/data discord-speaker
```

Проверка журнала:

```sh
docker logs --tail 50 discord-speaker
```

Для работы нужен исходящий доступ к Discord и сервису синтеза речи.
HTTP-сервер, публичный домен и входящие порты не требуются.

## Локальная разработка

Нужен Python 3.12+:

```sh
python -m venv .venv
```

Активируйте окружение способом своей ОС, затем установите зависимости и выполните проверки:

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Задайте `DISCORD_TOKEN` и при необходимости `DATA_DIR` в окружении процесса,
затем запустите `python bot.py`. При таком запуске файл `.env` автоматически не читается.
FFmpeg предоставляется зависимостью `imageio-ffmpeg`.

В репозитории также есть `railway.toml` для контейнерного развёртывания на Railway.
При использовании этой платформы задайте переменные окружения, подключите постоянный
диск к `/app/data` и оставьте одну реплику без засыпания.

## Проверка после запуска

После записи `READY` в журнале:

1. Откройте `/panel` и озвучьте фразу в обычном голосовом канале.
2. Убедитесь, что микрофон автора временно отключается и затем восстанавливается.
3. Назначьте канал через `/textchannel channel:…` и проверьте сообщения двух участников
   одного голосового канала.
4. Выйдите из канала участником, вызвавшим бота: бот должен отключиться и очистить очередь.

Подготовка речи зависит от внешнего сервиса. Проверки в CI выполняются без Discord;
подключение, слышимость и права необходимо проверить на своём экземпляре.
При обновлении старых установок оставшийся `GUILD_ID` используется только для очистки
устаревших команд и не ограничивает список серверов.
